# 审美标准（用户验收过的要求）

> 这些是用户在真实项目里提过、并验收通过的要求，**每次包装都要满足**。具体数值/文案/配色不在这里，看 `cases/`。
> 冲突时以用户当次要求为准；用户当次新提的通用要求，交付后追加到这里（注明日期）。
> **优先级：§0 投放原则 > 其余审美标准**。审美要求（简约、融入画面）和投放要求（清楚、够大、够快）冲突时，按投放要求做。

## 0. 投放原则（最高优先级，2026-10-30）
包装是买量素材，目标是转化，先保证“看得懂、看得清、想去玩”，再谈好看。

1. **玩法切入要快**：观众要尽早看到核心玩法。剧情选择类素材**尽快进第一个选项**：开头标题、铺垫、无台词段都要压缩，不能为了标题/氛围拖慢进选项的时间。定方案时在时间表里标出“第一个选项出现时间”，并说明为什么不能更早。
2. **重点元素要够清楚、够大**：剧情选择素材的重点是 **台词、好感度条、选项 UI、输入框**。这几样必须在手机上一眼看清：大字号、粗字体、强对比（描边/投影/底板都可以用），尺寸宁大勿小。“融入画面、简约”不能以牺牲清晰度和大小为代价。
3. **好感度条 = 目标 + 激励**：
   - 目标：一直让观众知道“要把它涨满/涨到多少”（满格位置、目标值清楚可见）；
   - 激励：**数值变化要大**（配数字滚动 + 放大/发光 + 音效），小幅度的 +1、+2 没有激励感。
   - 好感度**在选项和剧情关键事件处变化**（时间点对齐画面动作，2026-11-05），随剧情大起大落（可涨可跌），具体数值**按剧情手动定**，没有固定下限（用户 2026-10-30）。
4. **选项 UI 放在画面垂直中心偏下**：中下区域只给**选项 UI**——选项、输入框、用户发出的消息/指令气泡、角色回复气泡（对话类台词）。这一区域符合拿手机的视线和拇指习惯。**好感度条等进度条不属于选项 UI，不放中下区**：照原方案放角色头顶跟头（或用户指定的位置），只按 §0.2 放大、加清楚。仍要遵守“不挡脸”和“同一位置同一时刻只出现一个 UI”（§1）。（用户 2026-11-02 澄清）
5. **剧情结束后的转化承接**：剧情结束后的对话/承接段**参考产品本身的 UI 设计**来做（对话界面照产品真实界面），画面风格**参考商店页图片风格**，让观众点进商店时“看到的就是视频里的东西”。参考素材由用户提供，放在 `reference/投放参考/`（产品 UI、商店页截图）；**还没提供时先向用户要**，不要凭空设计一套片尾对话 UI。

## 1. 通用原则
- 用户说“重新设计 / 不合格 / 太丑” → **做新的**，不要在模板参数上小修小补。编辑器只负责呈现工程，图层可以全部自己生成。
- 改动都要能在编辑器里看到并微调：自定义图层用独立轨道（`X-*`），轨道名写中文用途。
- **出现的 UI 都要有入场动画**，不能一帧突然出现。（2026-10-20）
- **贴着人物的元素必须准**（跟脸的框、跟随文字、指向角色的标记）：用检测/跟踪得到位置，生成前先出“原帧 + 元素位置”的核对图自己看过；位置不准比不做更糟。（2026-10-20）
- **包装要融入画面，不突兀；简约、有高级感**（但服从 §0：重点元素的清晰度和大小优先）。否决过：粉色综艺字幕（“廉价”）、给所有 UI 都加玻璃框/气泡框（“气泡太丑”“不要给所有UI都加气泡框”）。（2026-10-21）
- **全片一套配色/字体/UI 语言**：后加的元素（手机屏、弹幕、目标等）也必须用同一套，否则 = “风格不统一”，要返工。（2026-10-21）
- 可选建议：主色从角色/画面取（如发色、服装、灯光色），更容易融入。（2026-10-21）
- **用户给了参考代码/页面就照参考做**：先把原文件抓下来（gitee raw 用 `curl -sL https://gitee.com/<user>/<repo>/raw/master/<urlencoded路径>`），按它的写法 1:1 移植，不能只学大意（“我都给你参考代码了还做不对”）。（2026-10-22）
- **每次画面切换都要留够时间**，让观众意识到剧情变了：片头→正片、选项点完、失败卡、进片尾，每个信息至少停 0.8–1 s（“没有给人接受信息留时间”“根本反应不过来”）。（2026-10-22）
- **同一位置同一时刻只出现一个 UI**：前一个完全退场，下一个才出现，不能叠在一起。（2026-10-22）
- **合理去标点**：句号、逗号这类不表达情绪又影响排版的去掉（句中的换成空格或换行）；？！这类表达情绪的保留；长音「〜」保留。去标点要同步改全量文案（规则 5，用户批准）。（2026-10-22）
- **用户指定参考某个工程的某一部分时，只参考那一部分**，其余按本素材剧情设计。（2026-11-05）
- **引用其他素材的画面只取原工程的原始素材**，不截已经包装好的成品。（2026-11-05）
- **生图等外部资源受阻时，先用视频帧占位把包装做完**，不卡住整体进度。（2026-11-05）

## 2. 标题 / 开头
- 可用**独占开场的分屏反差标题**（约 2–3 s，上下两个反差画面 + 斜向标题条 + Logo），正片接在标题之后，不叠在正片上；参考女警、女仆案例。（2026-10-22）
- **开头不能只做位移/淡入**（“纯位移动画太廉价”）：要逐帧特效，如冲击波、色散、闪白、震屏、粒子、速度线、扫光、推镜。（2026-10-21）
- **开头要有 Logo 图标**（MiraiMind 图标 + 字标）。（2026-10-21）
- 开头**不放剧情说明卡**（几行背景介绍被删过）；需要交代时用一个「目标」（如「目標：貞操を守り抜け」），文案先向用户申请。（2026-10-21）
- **不是必须的**。加的话要注意视觉传达和视频节奏：不能和进度条、台词、画面重点同时抢视线。（2026-10-20）
- **只在开头出现**（约 0–3.6 s），弹入 → 停留 → 淡出；不常驻全片。
- **不挡角色的脸**：先抽开头几帧看脸的位置，标题放在脸的下方（一般是画面 65–80% 高度），必要时把标题整体下移/缩小。
- 字要粗，有描边/投影，在亮暗画面上都能读。

## 3. 字体
- 字要**粗、清楚**；细字体（Medium 及以下）在手机上看不清 = 不合格。
- **日文必须用带假名的字体**。编辑器默认字体 `MM Paperlogy` 是韩文字体，没有假名 → 会退回成系统细体。JP 项目的气泡要显式设置 `module.params.font`。
- 已验收可用：
  - 气泡（JP）：`ZenMaruGothic-Black`，`fontSize: 50`（上传：`POST /api/fonts`，见 custom-layers §4）
  - 标题/进度条/片尾（JP）：`MochiyPopOne-Regular`（`%LOCALAPPDATA%\Microsoft\Windows\Fonts\`）
  - 内心独白（JP）：`KleeOne-SemiBold`（手写感）
  - 监控/HUD/识别文字（JP）：`DotGothic16-Regular`（像素感）；微恐片尾文案/大字：`ZenOldMincho-Bold` / `-Black`（2026-10-20）
  - 简约高级风（JP，2026-10-21）：字幕/UI `NotoSansJP-Bold` / `-Black`（`$APP/public/fonts/`）；标题、数字、片尾大字 `ShipporiMinchoB1-ExtraBold`（`C:/Windows/Fonts/01_诱惑台词主力_特粗标题_ShipporiMinchoB1-ExtraBold.ttf`）
- 已否决：`YuGothB`（游ゴシック Bold）用于字幕/选项/片尾 → “字体太丑”（2026-10-20）；`DelaGothicOne` + `ZenMaruGothic` + 粉色描边综艺风 → “廉价”（2026-10-21）。
- 生成前先检查字体是否包含所有要用到的字（fontTools `getBestCmap()`），缺字会掉成别的字体。

## 4. 对话 vs 内心独白
- POV 主角的内心独白**不能做成对话气泡**，要一眼看出是“心里话”：
  - 无气泡框；手写感字体；左右括号（ ）包住；
  - 文字分段逐块浮现（淡入 + 轻微上浮）；
  - 画面加暗角/压暗，让字从画面里浮出来。
- 角色说的台词才用对话气泡。
- 已验收的台词字幕形式（2026-10-21）：**无框**白字 + 柔和暗光晕，上方一个**小箭头指向脸**，字幕挂在脸下方并**跟着脸移动**（人脸跟踪）。
- **每句台词都要有一个重点词**：放大 + 强调色 + 发光 + 弹入。重点词从文案原句里选，不加字。（2026-10-21）
- 不管用气泡还是自己做的字幕，**出字时间都按逐字/逐词时间**；自己做的字幕句首用能量起点校正（ASR 句首常偏早）。整句一次出现或时间对不上 = 不合格。（2026-10-20）

## 4b. 选项
- 选完要有反馈：其他选项消失 → 选中项强调（闪烁/高亮）→ 再转场进下一幕；定格时长要给够，**不能一选就切**（“切换节奏过于快”）。所有选项都这样。（2026-10-20）点完后用户回复气泡至少停约 1.3 s 再转场。（2026-10-22）反馈要快：定格总长约 2.5–3.2 s，点完反馈约 0.5 s 后回剧情（“点击后过渡太长”）。（2026-10-27）
- **选项出来后不能马上点**：指针在不同选项之间**犹豫约 1.5–2 秒**再点击；最后一题可以一直犹豫不点，直接转场（钩子）。（2026-10-21）
- 选项界面可加**日本网感吐槽弹幕**（ニコニコ风，每题 7–8 条，横向划过，避开选项文字）；弹幕文案先向用户申请。（2026-10-21）
- 有「目标」时，选项界面要显示目标并加**闪烁强调**。（2026-10-21）
- 用手机/聊天界面做选项时：**手机只在进选项时出现**，平时台词用悬浮气泡。（2026-10-22）
- 倒数 3·2·1：每个数字停 1 s，在固定位置换数字。（2026-10-22）
- **B 路线选项默认样式**：只出选项、不显示提问；画面中下方胶囊 + 倒计时条（尺寸按 §0 要够大，2026-10-30 去掉“小尺寸”）；不全屏失焦，只压暗画面下半部分。替代 10-21 香槟案例的全屏失焦层（2026-10-27）

## 5. 进度/状态展示
- 不想要常驻标题时，可用**角色表情进度条**代替：节点 = 角色在各阶段的表情头像 + 阶段名（如 1日目/2日目/3日目），**无背景底板**，随剧情点亮。
- 钩子节点（锁）：最后一个节点上锁；**不要一直跳动**（最多入场一次）。结尾时锁飞到画面中心 → 开锁瞬间直接转场到片尾；**不要显示“解锁后”的内容**（如“制限解除”），保持钩子。开锁要配开锁音效。
- 数值类进度条（失望度/好感度）每次变化配音效 + 动效。~~每句台词都变一次~~（2026-10-22 规则，2026-10-30 用户改为：**好感度基本只在用户选择时变化**，可涨可跌，数值按剧情手动定；2026-11-05 扩展为选项和剧情关键事件处都可变化，对齐画面动作）。
- 好感度条要够大、够清楚，变化幅度要大，有明确目标（满格/目标值），见 §0.3。（2026-10-30）

## 6. 片尾
- 布局：**Logo 在最上面** → 文案 → 下载按钮 → 两个商店标（**大小一样**）。有聊天数字段时要显示聊天数。（2026-10-22）
- **风格延续正片**：字体、配色、UI 样式、背景（用片中的帧）都和正片是一套，不能是和正片无关的通用贴字/通用按钮。（2026-10-20）
- 文案**不加句号**（按 §1 合理去标点）。
- **片尾总长 ≤ 10 s**：元素依次出现、留够反应时间（约每 0.5 s 一个），手指连点约 0.3 s 间隔，点完就结束。进片尾前要有过渡（闪白/倒带等），不能一切就是片尾。（2026-10-22） 用户修改，替代“片尾约 2.3 s”）
- **片尾画面要和剧情逻辑对上**：例如做了时光倒流，片尾图就用倒流回去的那一帧，不能用倒流前的定格。（2026-10-22）
- 片尾背景亮度按题材定（恐怖/悬疑可以暗），背景图放在 V1，保证 V1 不空。（2026-10-20 用户删除“片尾必须亮”）
- **转化承接优先照产品 UI + 商店页风格做**（§0.5，参考在 `reference/投放参考/`）；下面的试玩广告 UI 只在用户没给产品参考时作为备选。（2026-10-30）
- 剧情后的软件功能展示**首选 `modules/app-ui` 模板**：`swipe` 划卡到角色详情（前面划走的卡用其他已上线素材的角色，最后停住的卡用本片角色），或者 `chat` 聊天界面。UI 可以精简，但**按钮必须和产品一致**；圆角图片不能有锯齿。（2026-11-02）
- 产品 UI 里**每张卡的名字、标签、简介都要填**，内容取自对应的原素材，文字不能超出版面。（2026-11-05）
- 进片尾前可加一段 **「AI 剧情对话」手机屏**：屏幕上是角色发来的消息和照片（照片截正片里的帧）。**版式严格照试玩广告 UI**（编辑器模板 `bubble/lgx`：灵动岛、居中头像 + 名字 + 在线点、分割线、左侧气泡、图片消息、输入中「…」），**配色和字体跟正片统一**。（2026-10-21）

## 7. 声音
- **音效优先用用户的音效库 `F:\钟海明\音效收集`**，库里没有的再自己合成。库里的音效（含清脆点击、弹出音）可直接用，不受下面“丝滑”限制；太小声的先提音量（ffmpeg volume + alimiter）。（2026-10-21）
- **自己合成的音效：丝滑**——柔和的 whoosh/swell/滑音，起止有淡入淡出、无硬瞬态。禁止：清脆音（tink/pop/叮）、叮咚、沙沙/嘶嘶声、雷声感的重音效。（2026-10-20 用户修改，替代旧的“苹果风格清脆音效”）
- 模板气泡的弹出音效如果是清脆/叮的音色，要关掉或换成丝滑音效；**“思考”音效默认关掉**（`module.params.sounds = {thinking: null}`，怀疑是沙沙声来源）。
- **人声清晰优先，BGM 也要听得到**：BGM 在台词处**按整句平滑压低**：提前压、说完多停一会儿再慢慢回升，两句之间的短停顿不回升，不用快速侧链压缩（“一惊一乍”，2026-11-05），不靠整体压低原声；原声里混有音乐/环境声时先做人声分离再提亮人声（“人声听不清楚”）。BGM 音量以听得清为准，而不是固定 0.2。（2026-10-27 修改，替代“原声压低到 0.35”）BGM 要贴合地区和情绪（JP 纯甜恋爱可用八音盒/电钢琴/轻 pad 的甜系）。
- **剧情类 BGM 必须有鼓点、三幕情绪递进**，不能平淡（“太平淡了”）：第一幕压迫律动 → 第二幕完整鼓组 → 第三幕高潮层（更密的鼓、主旋律）；每幕结尾加花/上扬接选项。**选项段撤掉鼓，换悬疑 pad**（用户认可）。（2026-10-21）
- **BGM 要有高级感 / drama 感**：GM 音色、MIDI+SoundFont 合成的“廉价”，八音盒叮叮当当也否决过。可用 MusicGen stereo-large 本地生成，再按时间轴切段拼接，关键重音（巴掌等）对齐画面（见女仆案例 `mg.py` / `bgm5.py`）。（2026-10-22）
- **消音哔声**要柔和、不吓人不刺耳，音量贴着原声；被打码的原声同时压低。（2026-10-22）
- 用户经常自己配 BGM：可额外交付**「无 BGM 版」**（保留原声和音效，选项段的悬疑 BGM 也保留），并告诉用户哪几段要避让。（2026-10-21）
- **视频模型生成的错误人声要去掉**：推倒/喘息等处常混进异常人声。检测：ASR 识别不出词但有能量，音高/频谱和角色声音不一致 → 对照画面确认 → 把那段 A1 静音（画面照常）。每条新视频都要单独查。（2026-10-21）
- **选项段 BGM 跟选项的时间结构走**：进定格一记重拍、倒计时期间滴答、点击一记重击（“BGM 没跟选项节奏”）。（2026-10-27）
- **剧情段和承接+尾板段用两首不同的 BGM**，交界处淡出淡入。（2026-11-05）
- 中间有黑幕/转场后也要有 BGM，不能断。
- 原声里**和前面重复的段落要删掉**（静音或剪掉 A1 那段）。
- 你听不到声音：交付时写清楚每条声音的来源/音量，并说“声音需要你听一下”。

## 8. 素材/人设图
- 人设图**不能有 AI 感/AI 画风**（用户否决过）。没把握时先问是否需要，或者直接用视频里的帧。
- 头像、进度条节点、手机屏里的照片都截**视频里的真实帧**，挑角色最帅/最好看的一帧（凑近、正脸、脸居中、裁紧，必要时提亮）；随手截的帧会被打回（“截图太丑”）。（2026-10-27）

## 9. 可选打法（已验收过的套路，按需选用，不是必须）
- 表情进度条代替常驻标题。
- 结尾用“锁 → 开锁瞬间转片尾”做钩子。
- 括号式手写内心独白。
- 自合成 BGM/音效（numpy 合成，见 `cases/*/synth.py`；注意该案例的清脆音效已不符合 §7）。
- 白闪转场（幕间切换、进片尾都可用）。
- 简约香槟风（逼迫向/强势女角色）：无框跟脸字幕 + 重点词 + 犹豫指针 + 吐槽弹幕 + 闪烁目标 + AI 聊天手机屏 + 鼓点递进 BGM，见 `cases/2026-10-21-JP-贞操逆转上门讨债-香槟简约/`。
- 液态玻璃手机聊天（参考 gitee 纯 CSS 液态玻璃 + 试玩广告聊天样式）、失败重试流程（超时 → 变灰 → 時間切れ → 説得失敗 + 3·2·1 → リトライ → 时光倒流 → 片尾）、巴掌特效（震屏 + 会淡去的屏幕裂纹 + 日文拟声字），见 `cases/2026-10-16-JP-女仆-液态玻璃手机/`。
